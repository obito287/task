Production System Architecture

This application has been crafted to fulfill all internship standards for enterprise full-stack development using semantic HTML5, modern CSS3 variables, and reactive vanilla JavaScript / TypeScript:

Frontend Layer Modular Vanilla JavaScript / TypeScript architecture with separation of concerns:
  • /src/services/auth-service.ts: Authentication
  • /src/services/task-service.ts: Firestore CRUD
  • /src/ui/toast.ts: Notifications
  • /src/ui/modal.ts: Accessible Modals
Backend & Persistence Managed Google Cloud & Firebase infrastructure:
  • Firebase Auth: Google OAuth Popups + Email/Password
  • Cloud Firestore: Enterprise instance
  • Real-Time Sync: Continuous onSnapshot
  • Zero Mock Data: Direct server persistence

Zero-Trust Firestore Security Rules (ABAC)

Security rules are mathematically enforced in firestore.rules and deployed directly to Cloud Firestore. Users can strictly access, read, and write only their own records: 

// Default Deny
match /{document=**} {
  allow read, write: if false;
}

// User-scoped Task collection
match /tasks/{taskId} {
  allow get: if isSignedIn() && isValidId(taskId) && existing().userId == request.auth.uid;
  allow list: if isSignedIn() && resource.data.userId == request.auth.uid;
  allow create: if isSignedIn() && isValidId(taskId) && isValidTask(incoming())
    && incoming().userId == request.auth.uid
    && incoming().createdAt == request.time
    && incoming().updatedAt == request.time;
  allow update: if isSignedIn() && isValidId(taskId)
    && existing().userId == request.auth.uid
    && incoming().userId == existing().userId
    && incoming().updatedAt == request.time;
  allow delete: if isSignedIn() && isValidId(taskId) && existing().userId == request.auth.uid;
}

Centralized Error Handling Protocol

Whenever any Firestore operation fails, our client code catches the error and serializes a structured JSON message containing detailed audit context for debugging: 

interface FirestoreErrorInfo {
  error: string;
  operationType: 'create' | 'update' | 'delete' | 'list' | 'get';
  path: string | null;
  authInfo: {
    userId?: string | null;
    email?: string | null;
    emailVerified?: boolean | null;
  };
}

1. Install Dependencies:

2. Start Development Server:

npm run dev

3. Build for Production:

npm run build

4. Verification / Linting:

npm run lint
